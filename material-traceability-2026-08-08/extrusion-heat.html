What was verified. James believed the existing Extrusion spec may already cover heat traceability. It half does, and the half that does is the better half:

✓ The data model covers it thoroughly. extrusion.run_cert_link stores cert_key_type in 'heat','serial','lot','batch' with reconcile_status, M:N against the run, per the Cert Identifier Index contract (sql/001_extrusion_schema.sql:166-180), plus run_material.lot_no (:149) and five pages of consumer obligations in REQUIREMENTS.md §3.3. This is a more complete traceability model than the one this spec proposes for WIP.
✗ The operator mockup captures no identifier at all. All 9 files — 5 operator frames, 3 supervisor frames, an index — of hpt-mockups/extrusion-log-2026-07-10/ were read. The only place a lot could land is operator-02-run-setup.html's Start notes, whose own design note reads “free-text for lot numbers / setup issues”. A notes box cannot be validated, indexed, or written to cert_key_value. So run_cert_link is a well-designed table with no operator-facing writer.

Why this is a proposal and not a WIP screen WIP's own config says so, as a James-approved decision. config.py:64-68 — “GA-WIP-192 (James, 2026-07-23): the scanner picker lists ONLY stations that emit WIP events today. Removed: Extrusion: lives in its own separate system (C:\Dev\Extrusion Log\), not WIP-integrated — emitting here would create orphan events.” Quoted in full — the second half qualifies the first: the same comment continues “It stays VISIBLE on the Hourly page as a scanning_yet: false ‘coming soon’ station via the scan_stations registry… This list gates emission; the registry gates display.” So Extrusion is still a registered, displayed station, and is a config.WORKER_ROLES value whose page role-model-and-navigation-2026-08-05.md §3.6 marks “New page needed (Phase 4)” (saying nothing about traceability). What it is not is in config.SCAN_STATIONS — so it emits no WIP events, and a gate that hangs off OP_FINISHED has nothing to hang on.
Building this in WIP would emit exactly the orphan events GA-WIP-192 removed the station to prevent, and would put a second writer in front of a table WIP does not own.
What should happen instead: file the §5.2 gap as a row in C:\Dev\Extrusion Log\GOVERNANCE_ACTIONS.md. A WIP session must not create it — spec §12 Q6.
Nothing on the frame is backed by production data. EXT-2, CBL-1250-BLK, RS-4471-B, GR-0729-4, CB-2214, die 0.625 in and 182 °C are all invented, and “required for this product code” implies a product→required-lots rule that exists in neither project. The only verified facts here are the three item-type rules and the run_cert_link table they would write to.
The rule itself still lives in the cross-cutting spec. §2 carries Resin → LotNumber, Grease and Colorant → Batch_x002f_Lot_x002f_Date_x002f, all hard, marked as Extrusion-Log-owned. That is the point of a cross-cutting rules doc: the rule is stated once, wherever the implementation lands.
