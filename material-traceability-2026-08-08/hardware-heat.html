Rewritten 2026-08-08 — James supplied the real mapping. Earlier drafts of this page drew an either/or for Anchor (heat or batch) taken from CertProcessor's HEAT_OR_BATCH sentinel. On the floor there is no either/or: both hardware item types are captured by Date Code.

Anchor → Date Code. Wedges → Date Code. One type, one control, no picker — which makes this the simplest capture screen in the set. The either/or has moved to Rebar, where it is real (Serial or Heat).

This is also the page where capture and cert-completeness genuinely disagree. CertProcessor requires HEAT_OR_BATCH for Anchor and Batch_x002f_Lot_x002f_Date_x002f for Wedges; DateCode is a real column but is warn-only on Anchor and not even listed for Wedges. So a correctly captured date code satisfies the floor gate and does not satisfy the cert rule. Frame B draws that honestly — spec §2.3.

Grounding — and what has no data behind it From James, 2026-08-08 (authoritative for capture): Wedge → Date Code, Anchor → Date Code. That is what is physically on the material and what the worker is asked for.
From CertProcessor (authoritative for cert completeness) — and it disagrees: "Anchor": {"required": [..., "HEAT_OR_BATCH"]} (:67-70) and "Wedges": {"required": [..., "Batch_x002f_Lot_x002f_Date_x002f"]} (:79-82). DateCode is a real column — FIELD_LABELS["DateCode"] = "Date Code" (:126) — but it is warn-only on Anchor (:69) and absent from Wedges' warn list entirely. Neither side is wrong; they answer different questions. The gate enforces capture, the sweep evaluates cert completeness, and spec §2.3 records the four rows where they differ instead of smoothing it over.
Why unverifiable_type is a distinct status: lumping it into unmatched would report a SharePoint schema limitation as a missing mill cert, and the §11 target of <3% unmatched would read as a floor-discipline failure. Spec §6.5.1.
Nothing here is backed by production data. Hardware kits have no schema — no kit entity, no component list, no per-component item-type mapping. Hardware is a live scan station (config.SCAN_STATIONS) and a live config.WORKER_ROLES value, but the kitting model on these frames comes from role-model-and-navigation-2026-08-05.md §3.5, not from code. Every part number, date code and kit ID is invented.
