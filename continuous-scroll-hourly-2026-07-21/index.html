MOCKUP — CONTINUOUS-SCROLL HOURLY VIEW (24h rolling window, past + future) · 2026-07-21 · not wired to live data.
Design intent:
  • Table columns are a rolling hour window: default 16h back + 8h forward = 24 cols. Scroll left for older; right for scheduled workload.
  • Header = 3 stacked rows: DATE (Mon 7/20 spans its calendar hours) → SHIFT (colored bands, cross day boundaries) → HOUR.
  • Day divider (bold vertical line) between calendar days. Shift bands cross it naturally — 3rd shift (22→05) shows as ONE continuous 8-column band. Solves the 3rd-shift discontinuity.
  • "Now" divider (thick blue vertical line) separates past (actuals) from future (SCHED cells, dashed, italic, from Rebar Optimizer's future-workload feature).
  • Rolling 24h chart on top preserved. All MES/OEE features preserved (KPIs, sparklines, vs-yest, DOWN, OEE toggle, alert, refresh).
  • Drill-down (NEW): click any operator hour cell to drop an inline lbs-per-bar-size panel under that worker for that hour (Machine → User → Hour → bar size). Rebar stations split by bar size; non-rebar (strand/hardware/lumber) and other show total-only; HPT-Cloud skeleton tags with no size yet bucket to Pending — backfill. One cell open at a time. tag_type comes from the scan_stations: block in machine-capability-matrix-v8.yaml — keyed on the scan-station name (not the routing names in machines:), so the benders missing from the routing matrix still split correctly.
