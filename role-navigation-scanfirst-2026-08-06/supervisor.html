6 / 7 · Supervisor — authority swap folded into the identity chip

The 2026-08-05 set spent a third stacked row on the Supervise OFF/ON toggle — app bar, then cross-role rail, then the toggle, roughly 150 px of chrome before any content. Rev 2 folds it into the identity chip that was already in the bar: 0421 W → tap → 0421 SUP. Still one bar. Still 38 px.

The swap stays explicit and audited — it opens a small sheet rather than toggling on a single tap, because every write after it logs a different authority. Frame A is that sheet; frame B is the supervisor view it produces.

Supervisor is the one role in this set that is not scan-first. Its pivot flips from a work unit to a person (audit R7), so there is no camera viewport and no context strip — the roster is the content. The bar is identical anyway, which is the point.

What changed from the 2026-08-05 authority-swap page 1. The Supervise row is gone. Authority lives in the identity chip that was already in the bar. Chrome for a supervisor drops from three rows to one.
2. Severity left the .val slot. The old roster put HIGH / MED in the same right-hand slot that holds 68% and 100% elsewhere — three data types in one place, the audit's open question §9.3. Here .val is always the progress percent (with a unit caption under it), and severity is a .pill plus the row's left border. Every list in this set follows that rule.
3. One status vocabulary. Roster subs read at machine / in staging / on truck / tag in office — the 6-stage lifecycle, everywhere, per the audit's §9.4 recommendation. The older ready / loading / not started wording is dropped.
4. Presence is dropped. The old page showed "4 of 5 on shift" and "Off shift · no cover assigned". There is no clock-in signal in the system, and the locked spec §12.5 records the decision that there is no software OOO handling. The header now reads "5 on the loader" — an assignment count, which is what primary_shift actually is.
Still unbacked: trucks (G4) · the worker↔load link that puts a person on a truck (G3) · the sign-off queue, which needs the unbuilt hpt-approvals primitive (S13) · the 0421 badge format (G14). Also note that "Supervisor" is not enforced in production today — PORTAL_ENFORCE_SUPERVISOR_ROLE is unset, so any authenticated principal passes, and authority_level does not exist in the data model yet. Names shown are placeholders, not roster data.
