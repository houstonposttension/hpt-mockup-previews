What this restores, and the terminology fix The green state existed only in the locked design. Last night I drew the short path and no success path at all. Frame A is the locked gate: the category breakdown, who loaded it, and "Clear driver to depart" — which is correct wording, because here the loader really is handing off to the driver.
The override is a form, not a sentence. Two numbered required fields, a 300-character counter, and a captured-photo state. Neither field is optional. The photo path reuses the existing unscannable- tag flow, so it introduces no new camera code, and /api/photo-upload is already fail-closed — if the linking PHOTO event can't be written the blob is rolled back and the upload fails. For an override that is exactly right: no evidence, no override.
Copy corrected throughout: Complete loading (not "Complete delivery run"), LOADING NOT COMPLETE (not "can't close out" — it states the fact rather than refusing), Override — finish loading short (not "ship short"), Why are you finishing without them?
Backend deltas still open: /api/photo-upload has no free-text field today, so the justification needs either a new note on the PHOTO event or — recommended — a distinct CLOSEOUT_OVERRIDDEN event carrying note + photo path, which keeps the upload contract unchanged and makes overrides queryable on their own. The run-level sign-off should be LOADING_COMPLETED; it must not reuse LOADED, which is per-tag.
