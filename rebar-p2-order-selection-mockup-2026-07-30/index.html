Locked decisions carried into this mockup

  1. Scope shape: System of four - shared shell + one high-fi + three sketch targets. Locks visual DNA in one push, avoids shape-drift across four one-off screens.
  2. Order data model: Native display of both sources with SOURCE: HPT / SOURCE: S97 badges. Common fields identical. Source-specific fields collapsed. Display convention only - not a data contract.
  3. Forecasted dates: Labeled placeholder - dashed underline + tooltip on every date, plus this page's banner. Real values wait on Phase 1 workload feed.
  4. Multi-select: Batch-only. Checkboxes + sticky footer. No per-card individual send button.
What this mockup is not.
* Not the operator's daily invocation surface - Shear97 tool stays CLI + printed pull sheets per Phase 1 PRD §6.
* Not a data contract - the dual-source card layout is a display convention. Phase 2 W1 build decides the actual API shape.
* Not driven by real data - every order id, weight, forecast date, and customer name is fabricated for shape validation.
* Not wired - no browser storage, no fetch, all inline CSS, native form controls only.

Visual DNA. Reuses tokens verbatim from vp-dashboard-portfolio-2026-07-27 and rebar-optimization-mockup-2026-07-30 (same --panel, --acc, status colors, chip / state-pill / risk-dot patterns). Two new source tokens --hpt (violet) and --s97 (teal) added for the SOURCE badges - orthogonal to the status palette so they don't clash.
